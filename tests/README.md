# Tests

Everything runs headless with `npm run test:all` (also run by CI on every push, see
`.github/workflows/test.yml`).

| Command | What it covers |
|---------|----------------|
| `npm test` | **Unit + integration.** Pure logic (CSV, formulas, text wrapping, zip, card sizes) and every main-process IPC handler running against real SQLite, sharp, resvg and pdf-lib. Electron itself is replaced by `tests/helpers/electron-mock.js`. `tests/integration/headlessCore.test.js` calls the services in `src/main/core` directly, with no IPC, to prove the core runs without a window. `tests/unit/textEngine.test.js` and `tests/integration/textEngine.test.js` cover the text engine (bundled fonts only; pixel comparisons against the rasterizer, fit modes, the move of an older project). `tests/unit/richText.test.js`, `richEdit.test.js`, `richLayout.test.js`, `tests/integration/richText.test.js` and `tests/e2e/richText.e2e.test.js` cover rich text (markup parser with a round-trip property test, toolbar edits, engine features, the version 8 migration, plain-text uses, import, conversion preview, and the cell editor by keyboard). `tests/unit/iconSvg.test.js`, `keywords.test.js`, `textControls.test.js`, `tests/integration/iconLibrary.test.js`, `textLibrary.test.js`, `textCheck.test.js` and `tests/e2e/textLibrary.e2e.test.js` cover the icon library, text styles, keyword rules, the text check and the text controls (SVG normalising, rule matching with a guard against slow patterns, every control at layout level, import with the safety limits, rename with references and undo, and the dialogs and properties panel by keyboard with axe). `tests/unit/svgImport.test.js`, `tests/integration/svgImport.test.js`, `tests/e2e/svgImport.e2e.test.js` and the fixtures in `tests/fixtures/svgImport/` cover the SVG import (the XML reader and its limits, style sheets, units and sizes, name matching, the clean-up report, hostile files, bound templates rendered for a card, re-import, and the dialog by keyboard with axe). `tests/unit/production.test.js`, `tests/integration/production.test.js` and `tests/e2e/production.e2e.test.js` cover the production PDF (colour conversion, ink limit and print colours, settings, every box, intent, spot colour, mark, layer and layout read back from the written file with pdf-lib and zlib, bleed in each template mode, profiles, saved settings, the version 9 to 10 upgrade, and the dialogs by keyboard with axe). `tests/integration/preflight.test.js` and `tests/e2e/preflight.e2e.test.js` cover the print preflight (a fixture card for every finding, each deliberately wrong, with the right card, template and element; a clean card; grouping, selection, ordering and the minimums; the export gate, Export anyway, the dialog and Show me by keyboard with axe). `tests/unit/presets.test.js`, `tests/integration/presets.test.js` and `tests/e2e/presets.e2e.test.js` cover manufacturer presets (the schema check of every shipped preset, the pixel arithmetic, duplicate, edit, import and export, applying a preset, per-card images at the preset's pixel size, the deck rule in the preflight, and the Preset menu, the Custom label and the dialogs by keyboard with axe). |
| | `tests/integration/displayName.test.js` covers the display name and the unique identifier of a set (the migration of a version 12 project, the triggers that keep the name right, edits that spread); `tests/integration/projectChanges.test.js`, `tests/unit/tableTokens.test.js` and `tests/e2e/tableTokens.e2e.test.js` cover the project's change signal and the table (groups of dice, colours, picture tokens, the middle button, the turn order); `tests/unit/help.test.js` checks the guide against the formula language and the text engine. |
| `npm run test:e2e` | **End to end.** Builds the app, then drives the real UI in Chromium. The app's real preload script is bridged over HTTP to the real main-process handlers, so UI, preload channel names and backend are all exercised together. Only the Electron window shell is missing. |

CI also runs a subset on macOS and Windows (`portable-subset` in `.github/workflows/test.yml`: rendering,
projects, card IDs, template library, snapshots and the production build).

Needs `poppler-utils` (`pdftoppm`) and `unzip` for the PDF/snapshot checks, and a Chromium
(`CHROMIUM_PATH`, or `npx playwright-core install chromium`).

Not covered (needs a real desktop): native menus/dialog windows, window chrome, the packaged
installer, and OS integration. Run the app once with `npm run dev` for those.
